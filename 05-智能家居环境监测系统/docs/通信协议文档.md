# 上下位机通信协议 V1.0

节点和上位机之间的串口协议。写代码前先把这个定下来，两侧按它各写各的，联调时只对 CRC 测试向量就能确认两边理解一致。

物理层：UART 115200-8-N-1，TTL 3.3V 电平（上位机侧经 USB 转 TTL）。

## 帧格式

小端序。帧头两个字节的用意是让解析端能在任意字节流里重新同步。

| 字段 | 长度 | 说明 |
|------|-----|------|
| 帧头 | 2 | AA 55 |
| LEN | 1 | 载荷长度，0~255 |
| TYPE | 1 | 帧类型 |
| PAYLOAD | LEN | 载荷 |
| CRC8 | 1 | 校验范围 LEN + TYPE + PAYLOAD |
| 帧尾 | 1 | 0x0D |

## CRC8

多项式 0x07，初值 0x00，输入输出都不反转、无异或。固件 protocol.c 和上位机 protocol.py 各有一份实现，标准测试向量 crc8("123456789") = 0xF4，两侧都过这个向量。

## 帧类型

TYPE=0x01 环境数据帧，节点到上位机，每分钟一帧：

| 字段 | 类型 | 说明 |
|------|------|------|
| node_id | u8 | 节点编号 |
| temp_x10 | i16 | 温度 ×10 |
| humi_x10 | u16 | 湿度 ×10 |
| lux | u16 | 光照 |
| smoke_adc | u16 | MQ-2 原始 ADC 值 |
| batt_mv | u16 | 电池电压 mV |

TYPE=0x02 告警帧，越限时立即发，载荷只有 node_id 和 alarm_code 两个字节。alarm_code：01 烟雾、02 高温、03 低温、04 高湿、05 低湿。

TYPE=0x03 应答帧，上位机到节点，node_id 加 ack_seq，暂时保留没用到。

## 容错约定

- 串口数据按任意长度到达，粘包分包都可能出现，解析端用状态机逐字节找帧头
- CRC 校验失败的帧直接丢掉并计数，不做重传，也不尝试按帧尾重同步（帧尾可能出现在载荷里）
- 节点侧传感器读取失败时发一个载荷全 0xFF 的环境帧，上位机按缺测处理
