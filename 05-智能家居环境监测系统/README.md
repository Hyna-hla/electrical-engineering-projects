# 智能家居环境监测

STM32 节点加 Python 上位机的室内环境监测。节点采温湿度（DHT11）、光照（BH1750）、烟雾（MQ-2），按自定义串口协议每分钟上报一帧；上位机解析、判限、告警、记 CSV、画趋势图。

```
[DHT11]  [BH1750]  [MQ-2]
    \        |        /
        STM32F103 ──UART 115200──> Python 上位机
```

没有硬件也能跑：host/simulator.py 会模拟节点 24 小时的数据（带误码注入），monitor.py 直接吃这个仿真流。接真节点的时候把 SerialSimSource 换成 pyserial 的串口读取就行，接口一样（read_chunk/finished），别的代码不用动。

## 协议

帧格式 AA 55 | LEN | TYPE | PAYLOAD | CRC8 | 0D，CRC8 用多项式 0x07，校验 LEN 加 TYPE 加载荷。固件 C 实现和上位机 Python 实现逐字节一致，verify.py 里有 CRC-8/SMBUS 的标准测试向量（"123456789" → 0xF4）可以核对两个字端有没有写错。字段定义见 docs/通信协议文档.md。

## 上位机解析

字节流状态机，逐字节找帧头，容忍粘包分包和噪声字节。这里踩过一个坑值得记一下：一开始找不到帧头就把缓冲区清空，结果帧头刚好跨两次 read 到达时会丢掉半个帧头，稳定丢帧 5% 左右；改成清空前保留末尾可能是 0xAA 的一个字节就正常了。verify.py 里专门有用各种不规则切分方式重放字节流的测试，防这个问题再犯。

24 小时仿真数据实测：1440 帧，按 0.5% 概率注入的误码 8 帧全部被 CRC 拦下，其余 1432 帧完整入库，有效率 99.4%。

告警规则和固件侧保持一致：温度 16~30°C、湿度 30~70%、烟雾 ADC 超 1000 报警。仿真数据里设计了一段 14:10~14:35 的烟雾浓度抬升（模拟消防演练），触发了 11 次告警，没有漏报。

## 固件

firmware/ 下是 STM32F103 + HAL 的实现：DHT11 的单总线时序（40bit 带校验和）、BH1750 走 I2C 读两个字节数、MQ-2 的 ADC 采样做了 8 次中值滤波。主循环按分钟采集上报，越限时立即补发告警帧。

说明一下：固件部分需要真实硬件才能完整调试，仓库里是代码实现，不含 CubeMX 工程文件；上位机和协议部分是可以直接跑、已经测过的。

## 运行

```bash
cd host
python monitor.py    # 仿真数据源, 出 CSV 和四张图
python verify.py     # 协议校验
```
